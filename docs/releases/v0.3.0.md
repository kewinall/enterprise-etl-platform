## 繁體中文

Enterprise ETL Platform v0.3 將可執行的 Airflow → Hop integration 升級為 **可稽核、可重試、可追蹤資料落地** 的 ETL lifecycle：

- PostgreSQL `etl_execution_log` 加入 `correlation_id`、`attempt_number`、`trigger_type`
- 新增 append-only `etl_execution_event`
- PostgreSQL trigger 自動建立 STARTED / SUCCEEDED / FAILED lifecycle events
- final status 自動寫入 `finished_at`
- 新增 persisted synthetic target `etl_data.synthetic_customer_daily`
- 新增 variable-driven Hop PostgreSQL metadata connection
- 新增 `audit_execution_start.hpl`
- 新增 `audit_execution_finalize.hpl`
- `synthetic_customer_daily.hpl` 改為真正寫入 PostgreSQL
- Airflow 使用 `run_id + try_number` 建立 retry-aware attempts
- 失敗先寫 FAILED audit，再交由 Airflow retry
- CI 實際驗證 attempt 1 FAILED → attempt 2 SUCCESS → 3 persisted rows
- 所有 Sample Data、Hostname、Credential、Schema 使用 synthetic / generic values

v0.3 不包含 container image build/promotion、offline image bundle、checksum/signing；這些保留給 v0.4。

## English

Enterprise ETL Platform v0.3 upgrades the executable Airflow-to-Hop integration into an **auditable, retry-aware, persisted ETL lifecycle**:

- Add `correlation_id`, `attempt_number`, and `trigger_type` to PostgreSQL execution audit
- Add append-only `etl_execution_event`
- Generate STARTED / SUCCEEDED / FAILED events through PostgreSQL triggers
- Set `finished_at` automatically for final states
- Add persisted synthetic target `etl_data.synthetic_customer_daily`
- Add variable-driven Apache Hop PostgreSQL connection metadata
- Add `audit_execution_start.hpl`
- Add `audit_execution_finalize.hpl`
- Persist the main synthetic pipeline output to PostgreSQL
- Use Airflow `run_id + try_number` for retry-aware attempts
- Finalize failures in audit before Airflow retries
- Validate attempt 1 FAILED → attempt 2 SUCCESS → 3 persisted rows in CI
- Keep all sample data, hostnames, credentials, and schemas synthetic or generic

Container image build/promotion, offline image bundles, checksums, and signing remain intentionally deferred to v0.4.
